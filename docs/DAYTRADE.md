# デイトレ（`daytrade`）— 寄付で買い、大引で売る

日本株のギャップ逆張り `jp_gap_fade` を回す CLI。根拠と数字は vault `20-research/2026-08-jp-daytrade-selection`
（検証の記録は 2026-09-07 に `~/obsidian-vault/20-research/` へ移した。[research/README.md](research/README.md)）。
設定は `config/daytrade/daytrade.toml`、実装は `pkg/daytrade/`（発注は `pkg/daytrade/execute`）。

## 規則（1 行で）

前夜に「プライム・売買代金 20 日中央値 1 億円以上・時価総額下位 1/3 除外・前日引け後の決算なし・
当日決算予定なし・日々公表信用残の対象でない・直近の本決算が赤字でない」銘柄を母集団にし、寄る前（8:59:50）の気配で
**ギャップ（寄付 ÷ 前日終値 − 1）が負の銘柄を並べた上位 N 銘柄**を寄成で買い（建たなかった残りは 9:00 以降の気配で成行。
下の「寄る前に出す」）、15:20 以降の成行売りで手仕舞う（15:25 以降ならクロージング・オークションで引け値）。持ち越さない。

**平常日の並べ方は gap_vol（ギャップ ÷ 20 日ボラの小さい順）**（`signal.rank_by = "gap_vol"`、2026-09-20〜）。寄る前の気配（8:59:50）で
並べる形では、気配の誤差で LightGBM の優位が消えるため（下の「並べ方」、vault `20-research/2026-09-jp-daytrade-rankby-preopen-fair`）。
**米国小幅高の日は「LightGBM で並べ、前日終値 −1.5% の寄指を寄る前の回に出すだけ」**（2026-09-21〜。ショートと 9:00 以降の回は休み。
`signal.rank_by_us_low = "lgbm"`・`regime.us_skip_legs = "short"`・`execution.preopen_limit_pct_us_low = 1.5` の 3 つが組。
下の「米国小幅高の日だけ寄指で出す」）。**止めるときは `us_skip_legs` の 1 行を `"all"` にする**（この日は両脚とも休む形に戻る）。

`rank_by = "lgbm"` にすると **LightGBM の予測値の高い順**に並べる（`pkg/daytrade/rerank`。2026-09-18〜19 は平常日もこの設定だった）。
どの並べ方でも候補・帯・N の取り方・業種の上限・配分は変わらず、並べる順番だけが変わる。gap_vol の順位と
「gap_vol なら選んだ銘柄」は順位表の履歴に毎日残す（下記「履歴」）。gap_vol で並べた日は LightGBM の予測値が順位表に残らないが、
気配（`quotes`）と母集団（`plan`）の履歴から `test/dt_live_shadow.py` で並べ直せる。

N は資金から決める: `N = round(max_capital ÷ order_budget)`（200 万円 ÷ 67 万円 → 3）。
1 注文は `max_capital ÷ N`。手数料は立花証券の定額コース（`daytrade.fees`。現物は 1 日の約定代金
合計で段階、信用は 0 円）。現物の段階は合計で決まるので、1 注文の大きさより「その日の合計が
段階の境目を越えるか」が効く。`order_budget` の既定 67 万円は旧来の一律手数料を前提に研究した値で、
定額コースでの最適値は再検証していない。

  「ショートの総予算 − 今日建てたショート − 今回の選定」で、前の回の余りを数え直さない
- `open` / `close` は 1 回の実行に**締め切り**を持つ（`execution.max_run_seconds` と時間帯の終わりの早い方）。過ぎたら新しい注文は送らず、送信中の電文は打ち切る。時間帯の外に成行を出さないためと、遅い日に 1 回がロックを握って次の回を潰さないため
- `close` は台帳の買いだけを売る。**ブローカーの建玉を無条件に売らない**（積立の保有を守る）
- `close` の失敗は持ち越しになるので必ず通知する（Discord の `WBJP_ALERT_CHANNEL_ID`）
- IV ゲート（`regime.iv_gate`）は前日の日経 225 オプション `BaseVol` 中央値。オプションの足は夜遅く（0 時ごろ）に乗るので
  20:30 の plan には無く、`open` が朝のアーカイブから取り直す。無ければゲート無しで進む（警告ログ）。
  取り込みは 0 時を過ぎてから取りに行き、0 行なら 50 分おきに取り直す（`archive.EmptyRetryInterval`。cron は 30 分おきなので、
  1 時間ちょうどにすると「1 時間後」の回が数秒足りずに落ちて実効 90 分になる）

## 配分と縮小（MaxDD 対策）

最大 DD は急落ではなく「効かない期間が続く」型（2025-10〜2026-02 の 4.5 か月で −50 万）。対策は 2 つで既定で有効:

- **ボラの逆数で配分**（`capital.weighting = "inverse_vol"`）: 上位 N の中で、20 日の日次ボラが大きい銘柄を少なく、
  穏やかな銘柄を多く持つ。利益 +8%・Sharpe 2.02 で DD は同じ
- **資産曲線で縮小**（`regime.equity_curve_days = 20` / `equity_curve_scale = 0.5`）: 直近 20 日の実現損益（台帳）が 0 以下なら
  その日の資金を半分にする。縮めている日は全体の約 2 割

資金が増えて DD の絶対額を許容できるようになったら、「順位順に 1 銘柄の上限まで詰め込み、余りを次点へ」（資金稼働 83%→96%、
利益 +9%、DD +12%）を再検討する（研究ノート「配分規則の比較」）。

### 保証金で上限を下げる（`pkg/daytrade/margincap`）

設定の `max_capital` は**狙いの水準**で、その日それを本当に建てられるかは委託保証金で決まる。
朝 8:53 の `warm-margin` が立花証券から保証金を取って `data/daytrade/margin.json` へ焼き、
9:00 からの `open` がそれを読んで上限を**下げ方向のみ**上書きする（`cmd/daytrade/margin.go`）。
前夜に取らないのは、代用有価証券の評価替え（前営業日終値 × 掛目）が夜間更新で確定するため。
キャッシュは日付と**取得時刻**の両方が当日でなければ使わない（前夜の値へ黙って落ちない）。
VIX（`usmarket`）と同じ形で、`open` は朝にブローカーへ繋がない。

**増えたぶんは勝手には使わない**——代用有価証券の ETF は日本株と一緒に下がるので、下げた日に建玉も
縮めると底で縮小して戻りを取り逃す。上げるのは人が `max_capital` を書き換えたときだけ。

- 建玉合計 = 信用新規建可能額 ÷ 1.3（ショック日の目減り、最悪 −11% への余裕）。
  脚への割り振りは**設定の `max_capital` の比そのまま**——固定の比を置くと、保証金が減った日だけ
  設定と違う長短比に引き戻される。縮小はリスクを下げる操作であって、長短の方針を変える操作ではない
- `max_capital` を下げるときは `order_budget` も `max_capital ÷ N` で置き直す。
  N = `round(max_capital ÷ order_budget)` なので**片方だけ下げると N が変わり**、最悪 0 に落ちて
  その朝は何も建てない。上書き後に `Validate()` を掛け直し、N が 0 になったら alert を出す
- キャッシュが無い・当日ぶんでない・下げた設定が検証を通らない、のいずれでも設定の値で建てる
  （保証金が読めないことを理由に売買を止めない）
- 取得元は `CLMZanKaiKanougakuSuii`（6 営業日ぶん）。**当日の行だけを見ない**——正体不明の
  「その他拘束金」が後日の行に出る（実機で当日 0、2 日後 3,211 円）ので、建てられる額は最小を採る

## ストップ高・ストップ安

- **寄りでストップ高**: ギャップが正なので買い対象にならない。保有中にストップ高になれば買い殺到の板なので売るのは容易
- **寄りでストップ安**: ギャップダウンの候補に入るが、**買わない**（`signal.skip_limit_down`、既定 true）。
  売り殺到の板では買いは即約定するが、引けの売りは板に買いが無く**約定しない＝持ち越し**になる。研究では
  ストップ安に触れた日の取引は 78 件（1%）で勝率 9%・平均 −14,156 円、うち 53 件は引けもストップ安だった
- **保有中にストップ安**: 15:20 以降の売りが約定しないことがある。引け後の `daytrade verify`（15:40）が
  売りの約定をブローカーに照会し、売れ残りがあれば通知する（`daytrade.carry`）。**翌朝の `open` が
  寄付の成行で自動的に手仕舞う**（下記「持ち越しの扱い」）。
  バックテストはショートと同じく `margin.carry_penalty` で「翌寄りで売った」ことにして織り込む（研究では 0.5%）

## 信用売りの脚 `jp_gap_up_short`（`config/daytrade_margin`）

`config/daytrade_margin/daytrade.toml` は `extends = "../daytrade"` でロング側の規則を `config/daytrade` から
継ぎ、資金（`[capital]`）と `[margin]` だけを書く。ロング側を直すときは `config/daytrade` を直せば両方に効く。
子に同じ項目を書けばそちらが優先される（配列は丸ごと置き換え）。

立花証券 e支店（信用手数料 0 円）で、ロング `jp_gap_fade` に**信用売り**の脚を足す。根拠と数字は
vault `20-research/2026-09-jp-gap-up-short`。

**規則（1 行で）**: 前夜に「貸借銘柄（`Mrgn == 2`）× プライム × 売買代金 20 日中央値 1 億円以上 × 前日引け後の決算なし ×
当日決算予定なし × **売り禁でない**」を母集団（plan の `short_eligible`）にし、9:00 の気配で
**ギャップ（寄付 ÷ 前日終値 − 1）が +5% 以上の銘柄を大きい順に N**（既定 3、1 注文 67 万円）成行で新規売り、
15:20 以降の成行返済買いで手仕舞う。常時建てる（ロングの資産曲線の合図には連動しない）。

- 母集団はロングの `[universe]` と**別**（`[margin]` の `segments` / `min_turnover` / `exclude_*`）。ショートは小型に効きが厚いので
  時価総額の分位で外さず、日々公表・注意喚起・増担保も外さない（建てられる規制銘柄に効きの差は無い）。
  **売り禁**（日証金の申込停止。`markets/margin-alert` の `PubReason.RestrictedByJSF`）だけ外す——新規売りが出せないため
- **TOB・MBO・締め出し（株式併合・株式等売渡請求）・上場廃止の開示が出た銘柄は外す**（`exclude_corp_events`、2026-09-15〜）。
  買付価格までサヤ寄せしてストップ高に張り付き、返済の買いが通らない（2026-09-15 に 8848 を売建てかけた）。
  判定は `news.Classify`（TDnet 適時開示の見出し。対象会社の「当社株券等に対する公開買付」と、買付者側の
  「（証券コード：NNNN）」の対象だけ。買付者・自己株式の公開買付・買集め・一部報道は外さない）。
  直近 `corp_event_lookback_days`（120 暦日）の開示を、**open の時点の記録簿**で付け直す（plan でも付けて parquet の
  `corp_event` 列に残す）。記録簿の最後の取り込み（成功）が `corp_event_max_staleness_minutes`（90 分）より古いか
  読めなければ、その回の**ショートを見送る**（ログ `daytrade.news_stale`。ロングは止めず、余りの回し先の設定に従う）。
  外した銘柄はログ `daytrade.corp_event`、`open_run` の `corp_excluded`。判定の一覧は `news events`。
  **検証では効かない**（電文が 2026-06-17 からしか無い）。
- **建てた後に分かった材料は `daytrade guard` が処置する**（`cancel_on_corp_event`、場中 10 分おき、時間帯は
  `execution.guard_window`＝09:00〜15:19。引けの手仕舞いと重ねない）。処置の残りが台帳に無ければ接続しない。8:52 の取り込み〜open の間や
  場中の公表で建ててしまった売建を、未約定なら取消、一部約定なら残りを取消して**取消の完了（最終の約定数量）を照会で確かめてから**
  約定分を成行で返済買い、全部約定なら返済買い。返済の注文 ID の種は引けの手仕舞いと同じなので、15:20 の `close` は重ねない。
  取消の完了を確かめられない・照会できない注文には何も送らず通知する（ログ `daytrade.corp_guard`）。
  台帳は「一部約定の後に取消・失効した注文」を死んだ注文と数えない（`ledger.Order.IsDead`）——建玉は約定分だけ残るので、
  open の再実行は枠を埋め直さず、引けの判定は台帳外の建玉として二重に返済しない。
  ストップ高に張り付いた後の返済買いは約定しないことがあり、そのときは `verify` の持ち越し通知 → 翌朝の `open` の返済に乗る
- 決算翌日のギャップアップは順張り（−30 bp/取引）なので必ず外す。プライム限定なのは**張り付き**（下記）のため
- 検証（2017-01〜2026-09、現金 200 万・ロング 300 万 N3 + ショート 200 万 N3・滑り 5 bp・12 月休みと前夜の米国ゲート・
  ショック日のロング ×1.5・ショートの 1 注文 100 万上限・余りをロングへ込み）: 合算 2,110 万 / Sharpe 2.52 / MaxDD −82 万、
  うちロング 1,685 万 / 2.23 / −108 万、ショート 425 万 / 1.06 / −75 万（張り付きを全額計上）。負け年 0。
  `daytrade backtest --config-dir config/daytrade_margin`

**最大のリスクは張り付き**: 引けがストップ高（買い気配に張り付き）だと返済買いが約定せず持ち越しになる。研究では
全区分で 5.4%（プライム 2.1%）、翌朝までにさらに平均 −425 bp。場中の損切りは逆効果（往復ビンタ）で、
対策はプライム限定と、`verify`（15:40）の持ち越し通知 → **翌朝の `open` が寄付の成行で自動返済**。バックテストは
`margin.carry_penalty`（既定 1.0 = 張り付きは全て翌寄りで返済したとみなす）でこれを織り込む。実際の約定率は運用で測り、係数を決める。

### 持ち越しの扱い（`execute.CarriedPositions` / `ReturnCarried`）

`open` と `close` は冒頭で、直近 14 暦日の台帳を遡って**手仕舞えていない建玉**を探す。残り株数は
「建玉の約定 − 手仕舞いの約定」で出し、ブローカーの建玉と突き合わせる
（建玉が無ければ手で返済済みとみなして対象外。照会できない注文がある銘柄は数量を推測せず、
通知して対象外）。ブローカーに聞くのは**台帳で未確定の注文だけ**（`verify` が走らなかった日の手仕舞い等）。
確定済みまで聞くと、14 暦日ぶんで 1 実行に百を超える電文になり、寄付の発注より前にそれを消費する。
建玉の照会は 1 実行に 1 回（現物と信用で 2 電文）で、持ち越し・台帳外・発注直前の台帳外検査が同じ結果を使う。
気配の時価問合も発注に使っている接続で送る（接続を増やさない）。見つかれば新規に建てる前に成行で手仕舞う——`open` なら寄付（板寄せに参加）、
`close` なら引け（朝に寄らず失効した分の保険）。

- 台帳には**建てた日の下**に記録する。その日の `verify --date` が「手仕舞い済み」になり、
  今日の手仕舞い対象（`close`）には混ざらない。再実行は client_order_id で冪等
- **拘束資金**: 持ち越しの残り株数 × 建値を脚ごとに合計し（保証金は 3 割でも評価損を抱えるので全額を拘束とみなす）、
  残り `max_capital − 拘束 − 今日建てた分` で建てられる件数に減らす（`execute.CapByTied`）。残りが 1 注文の予算に満たなくても
  **1 件を残りの金額で**建てる——一部が拘束されただけで一日を休むのは機会損失。0 件は残りが無いときだけ。
  返済注文を出していても、寄っていない銘柄の資金はまだ戻っていない。何日も寄らない銘柄は 14 暦日まで遡って追う。
  同じ脚の持ち越しが複数日にあれば、ブローカーの建玉を日をまたいで消費し、返済の合計が建玉を超えない
- **1 銘柄の上限**（`capital.max_order` / `margin.max_order`）: 候補が N に満たない日や拘束で枠が減った日に、
  総予算を 1 銘柄へ寄せない。実運用とバックテストで同じ値。ロングは 1 注文予算の 1.5 倍（`daytrade_margin` で 250 万）。
  **ロング側は成績には効いていない**——250 万・300 万・上限なしは 10 年の最大 DD が −1,120,227 円と 1 円まで一致する。
  損益は 150 → 250 万で単調に増えて 250 万で飽和し（10 年 2,739 → 3,309 万、+21%）、効かせたいなら 200 万以下にする。
  150 万に戻すと損益 −17% で Sharpe も下がる（2.95 → 2.90）ので戻さない（研究ノート `2026-09-jp-daytrade-max-order`、vault）
- 発注直前の「台帳に無い建玉」検査（`EnsureNoUnrecordedPositions`）は持ち越しを既知の建玉として差し引く。
  差し引かないと、持ち越した銘柄が今日も候補になった朝に発注が丸ごと止まる
- 建玉を照会できない朝は `open` を止める（持ち越しを知らずに建てると二重になりうる）。`close` は逆で、
  持ち越しを判定できなくても**当日の手仕舞いは続ける**（止めると今日の建玉が丸ごと持ち越しになる）。
  判定できなかったことは異常（`daytrade.carry_check_failed`）として残す
- 台帳に無い信用建玉（台帳を失った・発注後に記録できず落ちた）は自分の玉として成行で返済する
  （`execute.UnrecordedMargin`。現物は積立の保有かもしれないので触らない）。返済注文は建てた日が
  分からないので今日の下に記録され、**その銘柄は今日の候補から外す**——同じ銘柄を今日建てると、
  引けの手仕舞いがその返済注文を「発注済み」と取り違えて当日の建玉を残す
- 返済注文がまだ板に残っている（送信済み・一部約定）脚には**返済を重ねない**（`Carried.ExitOpen`）。一部約定で残り株数が
  変わると注文 ID も変わり、冪等の柵をすり抜けて生きている返済の上にもう 1 本出るため。拘束資金と台帳外の差し引きには数える
- 返済の送信結果が分からず PENDING になったら、次の回の冒頭で当日の注文一覧と突き合わせる。返済は建てた日の下に記録されるので、
  突き合わせる PENDING は台帳の日ではなく**発注時刻が今日**のもの。一覧が空で返った（今日送って注文番号の分かっている注文が
  1 つも載っていない）ときは「届いていない」と読まず、次の回に回す。送った回の中の判定も、締め切りで待ちを縮めたら次の回に回す
- 持ち越しは毎回ダイジェストの異常（`daytrade.carry`）として残る。自動で片付いても「起きた」ことは見える。
  `verify` の通知も「翌朝の `open` が自動で返済する。手で触らない」（手で売ると台帳と建玉が食い違い、朝の返済が反対建玉になりうる）

**尻尾は「候補 1 銘柄の日」**: ショートは候補が中央値 2 銘柄/日で N3 が埋まらず、候補が 1 銘柄しか無い日は総予算
200 万円がその 1 銘柄に乗る。10 年の最悪 20 取引のうち 13 件がこの日（金額 ≈ 200 万）で、N を増やす（4・5・6）・等金額・
極端なギャップの除外はどれも悪化した。**1 注文の上限 `margin.max_order = 100 万円`**で頭打ちにすると、ショート 509 → 428 万
（−16%）で Sharpe 0.87 → 1.03、MaxDD −117 → −75 万（分足 2 年でも同じ向き）。67 万は利益 −35%、134 万は DD −22% で、100 万が
Sharpe の頂点（vault `20-research/2026-09-jp-shock-days`）。

**ショートの一時停止**（`margin.paused = true`、2026-09-18〜）: ショートは建てず、枠 200 万を毎日ロングへ回す
（ロングは 4 銘柄 × 175 万。米国小幅高で「ショートだけ休む」日も回し、ショック日は回さない）。9:00 以降の特別気配は
+5% 以上のギャップを平均 −6.9pt 潰すので、9:00 以降の気配で選ぶショートは 2 年の模擬で平均が負だった
（vault 20-research/2026-09-jp-daytrade-preopen-order）。寄る前の回の気配で選ぶショートを 20 営業日の記録で測り直したら外す。
一時停止中は open がショートの気配を取らず、ニュースの記録簿の鮮度も見ない。SELL の順位表も積まない
（0 件の順位表を「候補なし」と読ませないため）。画面は「ショート: 一時停止中（margin.paused）」、
open の要約は `short_paused = true` で `short_n` / `short_multiplier` は空。見送りの日の「建てていたら」
（`evaluate.NominalLegs`）も同じ形で、架空の売建を作らず枠を丸ごとロングへ回す。

**余りはロングへ**（`margin.spill_to_long = true`）: ショートは候補 0 の日が 33%、1 銘柄の日が 29% あり、200 万の枠が
遊ぶ。使わなかった分（候補 0 なら 200 万、上限で頭打ちにした残り）をその日のロングに回し、ロングの銘柄数を
総予算 ÷ 1 注文の予算（切り捨て。`selection.SpillInto`。いまは 167 万、下の測定の頃は 100 万。`capital.max_positions = 10` が上限）に増やす。長短の合計は 500 万のままで保証金は変わらない。
10 年で合算 1,734 → 2,110 万（+22%）・Sharpe 2.38 → 2.52・MaxDD 不変、2 年（分足）で 442 → 541 万・Sharpe 2.90 → 3.18。
上限なしで回すとロングの DD が −142 万に膨らむので、**`max_order` とセット**（ただしこれは 1 注文予算 100 万・
上限 150 万の時代の測定で、予算 167 万・上限 250 万の現行では再現しない——上限なしと 250 万は 10 年の DD が
一致する。研究ノート `2026-09-jp-daytrade-max-order`、vault）。ショック日（ショート ×0）は回さない
（ロング ×1.5 = 450 万にさらに足すと保証金の枠を超える）。`open` はショートを先に決めて余りをロングに回す順序で動く。

ロング側は `jp_gap_fade` の DD 対策（合図の日に 1/2 に縮小）を**外す**（`margin.long_shrink = false`）。
信用買いなので建玉は現金より大きくでき、既定はロング 500 万円（2026-09-16 に 300 → 500 万。現金 200 万・保証金率 33%）。経緯は
研究ノート「信用売りでの下げ相場対策」「ロングの DD 抑制を外す」（vault `20-research/2026-08-jp-daytrade-selection`）。
`daytrade backtest --config-dir config/daytrade_margin`。

**発注側**: `[margin]` が有効なら `plan` は `short_eligible` / `jsf_stop` 列を持ち、`open` はロングを信用買い（`long_via_margin`）、
ショートを `short_eligible` の信用新規売りで出し（気配はロング・ショートの和集合で取る）、`close` は反対売買の返済
（買建→返済売り、売建→返済買い）、`verify` は脚（long / short）ごとに約定と建玉を突き合わせる。
台帳は `trade`（CASH / MARGIN_OPEN / MARGIN_CLOSE）列を持ち、資産曲線の合図は**ロング側**の実現損益だけで見る。
立花証券の電文は `pkg/wbcore/broker`（`tachibana.go`。売買区分 1=売 3=買、返済は建玉番号を個別指定、
51 単元以上の成行売建は事前に拒否）。売建の株数は `selection.PickFrom` が 50 単元で頭打ちにする
（低位株は予算を使い切れないが、拒否されて建てられないよりよい。バックテストも同じ上限）。
気配は `quote_source = "tachibana"` で、ギャップは立花証券の基準値段（前日終値 `pPRP`）で出す
（分割・併合の日にアーカイブの調整前終値で −50% のギャップに見えないため）。
残る未対応: 当日に新たに売り禁になった銘柄（前日公表分しか除外できない。発注時のエラー 11149/11325 で弾かれ、
次の回で再送されない＝機会損失のみ）。

## 気配の取得元

取得元は立花証券の時価問合。`daytrade quotes 7203 9984` で疎通を確かめる。

| `quote_source` | 中身 | 用途 |
|---|---|---|
| `tachibana` | 立花証券 e支店 API の時価問合（`CLMMfdsGetMarketPrice`）。始値 → 現在値 → 最良気配の順に値段を決める | 本命 |
| `csv` | `symbol,price[,at]` のファイル | 検証・dry-run。別経路で取った気配を流す |

**寄り前と未寄付の銘柄は始値（`pDOP`）も現在値（`pDPP`）も空で、値段は最良気配（`pQBP` / `pQAP`）に
しかない**（2026-09-11 に実機で確認）。板寄せで約定が 1 件も無い銘柄には値段が存在しないため。
取る列は `pDOP,pDPP,tDPP:T,pPRP,pQBP,pQAP`。気配が両方あれば中値、片方だけならその値を使う。

1 リクエストは 120 銘柄まで。分割したバッチは応答を待たずに**番号順に 50 ms ずつずらして送る**（立花は届いた順に `p_no` を
検査するので、同時に送ると `p_errno=6` で弾かれる。弾かれたバッチは直列で取り直す）。直列に戻すなら cron の行に
`TACHIBANA_PRICE_STAGGER_MS=0`（bin の作り直しは不要）。実機の記録は [BROKER_VERIFY.md](BROKER_VERIFY.md)。

ここを見ないと、**ギャップが深い銘柄が丸ごと候補から消える**。ギャップの深さと寄り付きの遅さは
同じ現象の裏表で、495 営業日の実測では ≤−3% の銘柄は 9:00 にほぼ 100% が未寄付、
9:00 にすんなり寄る 90% の銘柄の寄→引は −0.4 bp（＝何も無い）。

### 選び方と時刻（2026-09-11 の結論）

9:01 に成行を出せば、未寄付の銘柄も**板寄せに参加して寄値で約定する**。待つ理由は無い。

| 選び方（9:01 成行・決算除外・495 営業日） | net bp |
|---|---|
| 上限（寄値を知っていれば） | +16.8 |
| **今の実装（寄済み＋未寄付を気配で）** | **+7.6** |
| 寄済みだけ（板を見なかった頃） | +2.0 |
| 未寄付だけ（`skip_opened = true`） | −1.7 |

決定時刻を遅らせるとどの帯でも悪化する（既に寄った銘柄の反発を払うため）。ギャップの足切りも
入れない（bp は上がるが稼働日が半減し、5 年の backtest でロング 980 → 300 万円）。
根拠は研究ノート `2026-09-jp-open-time-gap`。

### 既に寄っている銘柄を外す（`signal.skip_opened`）

真にすると、受け取った気配に**始値が入っている**銘柄（＝もう寄った）をロング・ショートの両方の
候補から落とす。分足の検証では合算 492 万 → 529 万（2 年、9:01 建て・15:20 手仕舞い）。

**既定 false のまま。開けてはいけない。** 上の数字は「未寄付の銘柄を正しい順に並べられる」前提の
もので、実際の順位付けは板の気配に頼る。板寄せ中の気配は真のギャップを**深いほど大きく圧縮する**
（真の −7% → 観測 +2%、真の −4% → 観測 −2%）ため、未寄付だけで戦うと net −1.7 bp になる。
設定に関わらず、受け取った気配が寄っていたかは `history/quotes` の `opened` 列に毎日記録する。

### 寄る前に出す（`execution.preopen_legs`）

**2026-09-19 から本番はロングを寄る前に出す（`preopen_legs = "long"`）。**

9:00 以降に気配を取ってザラ場の成行で建てる形では、寄っている銘柄（ロング候補の 89.4%）は
寄付の直後の値を追いかけて買い、板を食う分だけ負ける（板の記録の実測で 49.1 bp、実約定 16 件の
中央値 67.7 bp）。寄る前（crontab の `DT_PREOPEN_AT`、いま 8:59:50）の気配で並べて**寄成**を出せば、全銘柄が始値で建つ。

| 脚 | 今の形 | 寄る前 | 差 | t | シード |
|---|---|---|---|---|---|
| ロング（lgbm） | −19.83 | +9.02 | +28.85 | +9.03 | 20/20 |
| ショート | −12.26 | +16.21 | +28.47 | +2.42 | 20/20 |

（bp/日。vault `20-research/2026-09-jp-daytrade-preopen-order.md` と `…-book-slippage`）

**寄成はザラ場の成行と別物。** 立花の電文では値段（`sOrderPrice = 0`）と執行条件
（`sCondition = 2`）が別項目で、コードでも `domain.OrderType`（成行のまま）と
`domain.OrderCondition`（`OPENING`）の 2 軸に分けてある。寄成はその銘柄の**始値を決める
板寄せ**に参加するので、9:00 に寄らず特別気配で切り上がる銘柄は、寄った時刻（9:07 など）の
始値で約定する。「9:00 の板寄せで約定しなければ失効」ではない。

**締め切りは 9:00:00（板寄せ）。** 寄る前の回だけコードが自動で切る（`RunDeadline`）——過ぎてから
届く寄成は、既に寄った銘柄の板寄せに間に合わず約定しない。送れなかった分は 9:00 以降の 7 回が
「残りの枚数」として従来のザラ場の成行で埋めるので、寄り前の回が丸ごと失敗しても今の形に戻るだけ。

**まだ確かめていないこと（承知のうえで開けている）:**

1. **`sCondition ≠ 0` は実機未検証**（[BROKER_VERIFY.md](BROKER_VERIFY.md)）。電文が拒否されれば
   台帳に REJECTED が残り、9:00 以降の回が従来の成行で建て直す（失敗として通知も出る）
2. **寄らなかったときにいつ失効するか**（前場引けか、大引けか、後場の寄付に参加するか）。
   ここが分かるまで「寄らない銘柄の枠をいつ諦めるか」は決められない
3. 寄る前の回の気配（8:59:50）と始値の誤差。事前登録では「20 営業日溜めてから測り直して本番」としていたが、
   **記録を溜めながら運用する判断に変えた**（2026-09-19）。上の数字は 8:59:00 の誤差モデル
   （5 営業日）で測ったもの

台帳の `condition` 列に寄成かどうかが残るので、あとから滑りを寄成とザラ場の成行で分けて測れる。

#### 寄指にする（`execution.preopen_limit_pct`、既定 0 = 寄成のまま）

正の値を入れると、寄る前の回の**ロング**は寄成でなく**寄指**（指値 × 執行条件「寄付」）で出る。指値は
前日終値 × (1 − x/100) を呼値に切り下げた値（`execute.OpeningLimitPrice`。TOPIX500 でない粗い刻みで丸める）。
寄指は寄成と同じ板寄せに参加し、**始値が指値より下のときだけ、指値でなく始値で約定する**。

- **狙い**: 8:59 台の気配で深く見えた銘柄の 3 割弱は、実際には −0.5% より浅く寄る（深く見える銘柄ほど見えすぎている）。
  その銘柄は 7 年とも 1 本 −8〜−15 bp。指値が浅いので、予想どおり深く寄る銘柄は必ず約定する——寄指は外れたときだけ効く
- **約定しなかった枠は埋め直さない。** 後の回の残り枚数（`execute.PlacedToday`）は、板に残った注文も、失効した寄付条件の注文
  （`ledger.Order.IsLapsedOpening`）も使った枠に数える。埋め直すと、浅く寄ったから見送った枠を滑りつきの成行で使ってしまう。
  **拒否・未送信は従来どおり埋め直す**（電文が通らなければ今までの形に戻る）
- 失効は失敗ではない。`close` が `daytrade.opening_unfilled`（info）に件数と銘柄を残す
- 前日終値が無い・呼値に丸められない銘柄は寄成のまま出す。ショートは対象外（測っていない）
- **`backtest` には入っていない**（選んだ銘柄は全部が始値で建つ想定のまま。毎回その旨を印字する）。寄指の模擬は
  `test/dt_limit_breakeven.py`、本番の気配での影の記録は `test/dt_live_shadow.py` の `gap_vol_limit` の行
- 数字は模擬の探索の値（0.5% で +1.87 bp/日、t 3.22。事前登録した設定は 2 本とも不採用）。vault `20-research/2026-09-jp-daytrade-limit-on-open.md`
- **立花の「指値 × `sCondition = 2`」は実機未検証**（[BROKER_VERIFY.md](BROKER_VERIFY.md) の「寄指のプローブ」）。通してから 0.5 にする

#### 米国小幅高の日だけ寄指で出す（`execution.preopen_limit_pct_us_low`、2026-09-21 から 1.5）

前夜の米国市場が小幅高の日は、寄成・成行で建てるとどの並べ方でも −9〜−12 bp/日 なので両脚とも休んでいた。
この日に選ぶ銘柄は 3〜4 割が前日終値以上で寄ってしまう（1 本 −16〜−22 bp）。寄指はそれを落とす。
正の値を入れると、この日は次の形になる（`signal.rank_by_us_low = "lgbm"`・`regime.us_skip_legs = "short"` と組で使う）:

- **寄る前の回（8:59:50）**: `rank_by_us_low` で並べた上位を、指値 = 前日終値 × (1 − x/100) の寄指で出す。ショートは休み。
  平常日の `preopen_limit_pct` とは独立（平常日が寄成のままでも、この日だけ寄指になる。`config.Execution.ForDay`）
- **9:00 以降の回は両脚とも休む**（`usLowPreopenOnly`。見送りの順位表を積む）。寄る前の回が走らなかった・前夜の米国の値が
  寄る前に取れなかった（`us_stale` で待ち、後の回で小幅高と分かった）・寄指が拒否された朝は、その日は休みになる。成行では埋めない。
  **前夜の値が 9:12 を過ぎても取れない朝**は小幅高かどうかが分からないので、従来どおり平常日として取引する（`daytrade.us_stale` の異常に載る。この挙動は変えていない）
- LightGBM で並べられない朝は `FallbackToGapVol` が `us_skip_legs` を `all` に戻すので、従来どおり休む
- 指値を作れない銘柄（前日終値が無い・呼値に丸められない）は**発注しない**（`dropWithoutOpeningLimit`、`daytrade.opening_limit` の warn）。平常日の寄指は寄成に戻すが、この日の寄成は損の側
- 設定の検証: `preopen_legs` に long が無いと起動時に止まる。`us_skip_legs = "all"` は弾かない（米国のゲートが両脚とも止めて、この設定が眠るだけ）
- **`backtest` には入っていない**（この日のロングも全部が始値で建つ想定。毎回その旨を印字する）。模擬は `test/dt_limit_uslow.py`
- 数字は模擬の探索の値: LightGBM × 1.5% で +3.20 bp/小幅高の日（t 2.32、20/20、両期間、誤差 0.8 倍で t 3.01）、約定率 15%。
  事前登録した 0.5% は不採用（+0.76、t 0.38）。vault `20-research/2026-09-jp-daytrade-limit-on-open.md` の事前登録 3
- **戻すとき: `us_skip_legs = "all"` の 1 行だけ**（bin の作り直しは不要）。`preopen_limit_pct_us_low` だけをコメントにしてはいけない——
  `short` のままだと、この日のロングが LightGBM の寄成・成行で建つ（−11.6 bp/日 の形）
- **届かなかった寄指を自動で取り消す経路は 15:20 の `close` まで無い**（`protect` は約定 0 の注文を飛ばす）。立花が前場の寄付で失効させるなら問題ないが、
  後場寄りまで持つなら 12:30 に約定しうる（13:20 の保険と 15:20 の手仕舞いは掛かるので持ち越しにはならない）。最初の小幅高の日に [BROKER_VERIFY.md](BROKER_VERIFY.md) の 3 で確かめる

**費用の物差しが遡らないようにしてある。** `evaluate` の `cost_bp` は設定ではなく**その日の台帳の
`condition` 列**を見て寄付のスプレッドを免除する——設定で決めると `preopen_legs` を `long` にした
瞬間に、ザラ場の成行で建てていた過去の全営業日のロングの費用まで下がり、`20-research/結果.csv` に
残した数字と断絶する。約定が 1 件も無い日（候補なし・見送り・発注を開ける前）は払う側に倒す。

`backtest` は逆に**設定を全期間に当てる**——「もし寄る前に出していたら」を測る道具なので、それが
正しい。ただし同じ理由で `preopen_legs = "none"` の頃の結果とは物差しが違うので、
`daytrade backtest` は毎回その旨を印字し、`--csv` は `subject` に「（寄成 long）」の印を付ける
（`結果.csv` で 1 つの subject に別物が混ざらないように）。寄る前の気配と始値の誤差は
`backtest` には入っていないので、寄成の側は上限の数字。

#### 並べ方（平常日は gap_vol、2026-09-20〜）

寄る前の気配で並べる形では、気配の誤差が `lgbm` の優位を食い潰す。滑りを除いた上限（全銘柄を始値で建てる）は
`lgbm` +37.07 対 `gap_vol` +32.08 bp/日 で `lgbm` が上だが、**微細な順位に依存する `lgbm` のほうが気配の誤差に弱い**。
本番と同じく気配しか見えない形（実際は小幅高で寄るのに気配では負に見える銘柄も候補に入る）で 7 年を測ると、
常時 `lgbm` −2.23 bp/日 に対し「`gap_vol`・米国小幅高は休む」+2.93（差 +5.16、t 3.54、20/20 シード）。
2026-09-19 にいったん常時 `lgbm` にしたが（寄成なら、選ぶ銘柄の 65% が 9:00:00 に寄っている `lgbm` の滑りが消えるため）、
この検証で翌日 `gap_vol` に戻した。経緯と数字は vault `20-research/2026-09-jp-daytrade-preopen-order` と
`…-rankby-preopen-fair`。

**寄る前の気配の誤差が小さいと分かれば `lgbm` に戻す。** 測り方:

```bash
test/.venv/bin/python test/dt_preopen_rank.py    # 毎日の誤差と順位の再現度
test/.venv/bin/python test/dt_live_shadow.py     # 本番の記録から lgbm / gap_vol を並べ直して比べる
test/.venv/bin/python test/dt_rank_compare.py    # 20 営業日溜まったら実測の誤差で測り直す
```

## 危険信号（`[regime]`）

2018 年（−18 万円）と 2021 年（−19 万円）の負けは、**市場（TOPIX）が寄り高・引け安を 1 年続けた**ことによる
（TOPIX の寄り→引けが 2018 年 −7.1 bp/日、2021 年 −3.7 bp/日。戦略の日次損益は TOPIX の日中リターンと相関 0.5）。
買い持ちのデイトレは市場の日中ドリフトを背負う。前日までに観測できる信号を毎朝すべて計算してログ
（`daytrade.regime`）に残し、設定で有効にしたものだけが取引を止める。

| 信号 | 検証（2017–2026、200 万円・N3） | 既定 |
|---|---|---|
| 12 月を休む | 9 年中 7 年の 12 月がマイナス。IS +23 万・OOS +25 万、Sharpe 1.45→1.63 | **有効** |
| 前夜の S&P500 が 0〜+1% の小幅高（VIX ≤ 24） | その翌日は損益 ≈ 0（東証のギャップダウンが個別要因）。休むと Sharpe 1.45→1.63、閾値を動かしても崩れない。12 月休みと併用で合計 667 万・Sharpe 1.85・MaxDD −50 万・全年黒字（IS 1.62 / OOS 2.10）。ただしこれは gap_vol で並べた場合。寄った後の気配で LightGBM が並べるロングはこの日も +20.95 bp/日（t 3.79）稼ぐ（研究ノート 2026-09-jp-daytrade-ml-skip-days）が、寄る前の気配では寄成・成行だとどの並べ方でも負ける。2026-09-21 からは、ショートを休み、ロングは LightGBM × 寄指 −1.5% を寄る前の回に出すだけ（`us_skip_legs = "short"`。上の「米国小幅高の日だけ寄指で出す」） | **有効（ショートは休み、ロングは寄指だけ）** |
| 市場の日中ドリフト（TOPIX 寄り→引け 20 日平均 ≤ 0） | 2018 −18→+13、2021 −19→+53 に転じるが、2022 年以降の利益を 3 割削る（IS 限定） | 無効（記録のみ） |
| 資産曲線（戦略の直近 20 日損益 ≤ 0 なら資金を半分） | 休むのではなく縮める。ボラ逆比例の配分と合わせて MaxDD −50→−30 万、利益 −2%、Calmar 1.31→2.14 | **有効** |
| IV（前日 ≤ 18） | CAGR 維持で MaxDD 半分、稼働 5 割 | 無効 |
| **ショック日**（市場ギャップ ≤ −2% か前夜の S&P500 ≤ −2%） | 止めるのではなく**増やす**。市場ギャップ ≤ −2% の日は +7.8 万/日（t = 6.2、勝率 78%、IS/OOS 一致）で最良の日。翌 5 日も基準の 2〜3 倍。効くのはロングだけ（ショートの勝率 16〜26%）。予定された経済イベント（FOMC・日銀・雇用統計・選挙）は何も出ない。信用の設定でロング ×1.5・ショート ×0: 10 年で合算 +10%・Sharpe 2.09 → 2.19、MaxDD 不変、建玉は通常の 500 万を超えない（vault `20-research/2026-09-jp-shock-days`） | 土台は記録のみ、**`config/daytrade_margin` で有効** |

米国の信号（S&P500 / VIX の終値）は朝の `warm-us` が取って `data/daytrade/us.json` に焼き、`open` は読むだけ
（焼けていない朝だけ `open` が取りに行く。上の「1 日の流れ」）。取得元は Cboe（公式の日次履歴）で、
落ちていれば Yahoo Finance（chart API。非公式で、ブラウザ風の User-Agent が要る）、それも駄目なら
FRED（`SP500` / `VIXCLS`。前夜の値が出るのは 9:10 JST ごろで、寄付の早い回には間に合わない）に切り替える。
前夜（NYSE の直近の取引日。祝日は飛ばす）の値がまだ無い回は `regime.us_stale_wait_until`（設定は 9:12）まで
判定せずに見送り（`daytrade.skip` の `us_stale`）、過ぎたら手元の最新で判定して `daytrade.us_stale` を異常に載せる。
取れなければ信号なしとして取引する（`daytrade.us_missing`）。
市場ギャップ（候補の中央値ギャップの絶対値 > 1%）の日はドリフトのゲートを無視する。急落・急騰の寄付は
逆張りが最も効く日（+1.7 万円/日）。
ドリフトのゲートを入れる場合は `drift_gate = -0.0003`（−3 bp）を目安に。

## バックテスト

**`rank_by = "lgbm"` の backtest は学習期間（〜2026-09-16）と重なる**ので、成績は割り引いて読む
（仕組みの確認用。成績の比較は既存規則か、学習期間の外で）。

**費用には成行のスプレッドが入る**（`execution.spread_bp_open` / `spread_bp_close`、2026-09-18 から）。
成行買いは最良売気配で約定するのに、建値に使う分足・ティックは約定値（中値の近く）なので、
その差がどの検証にも入っていなかった。板の記録（`history/book`、2026-09-11〜09-18 の 6 営業日）の実測で
9:00:06〜08 のスプレッドは全上場の中央 53.1 bp（片道 26.6）・ギャップ −3〜0% の寄済み銘柄で 61.7 bp（片道 30.8）、
15:19 は 21.7 bp（片道 10.8）。**寄付のぶんは既に寄っている銘柄だけが払う**（未寄付は板寄せに参加して寄値で
約定するので払わない。分足の無い日は払う側に倒す）。往復コストは既定の設定で 5.7 → 43.7 bp になり、
2026-06-01〜09-18 の 77 営業日で損益 431 万 → 251 万円（−42%）、Sharpe 10.52 → 6.13。
**過去の検証の円の見積もりはこの分だけ甘い。** 6 営業日の実測なので、板が溜まったら測り直す。

```bash
daytrade backtest --since 2017-01-01          # 設定どおり（資金固定・100 株単位・段階手数料）
daytrade backtest --since 2022-01-01 --trades  # 直近と個別の取引
# 分足の約定値で（ザラ場の成行で建てる形＝9:01 の成行・15:20 の成行に近い）
daytrade backtest --since 2024-11-05 --fill-entry 09:01 --fill-exit 15:20
daytrade backtest --since 2017-01-01 --no-cache  # パネルのキャッシュを使わない（結果は同じ・遅い）
# 格子（複数の設定を 1 プロセスで）。パネルの読み込みは 1 回で済む
daytrade backtest --grid config/daytrade_margin --grid config/試作A --since 2017-01-01 \
  --csv /tmp/grid.csv --note 2026-09-なんとか
```

### 格子（`--grid`）

`--grid <dir>` を並べると、複数の設定を 1 プロセスで順に回す。パネルと危険信号の材料は
設定に依存しないので**読み込みは 1 回**、2 本目からは母集団の当て直し（`UniverseView`）と
`Simulate` だけになる。`extends` が使えるので、各 `<dir>` は既定の上に差分だけ書いた小さな
toml でよい。

- `--csv <path>` は `20-research/結果.csv` と同じ列（`note,system,market,kind,subject,period,
  metric,value,unit,role`）で書く。`subject` は `<dir>` の名前、`note` は `--note` の値
- **1 本だけなら `--grid` にする意味は無い**（`--config-dir` と同じ読み込みを 1 回払うだけ）。
  効くのは 2 本目から
- 10 年・設定 3 本の実測（2026-09-12）: 合計 70.7 秒（読み込み 18 秒 + 長短 22.2 / 17.9 秒・
  ロングのみ 9.1 秒）。設定ごとに回すと 37 + 37 + 28 = 102 秒

### パネルのキャッシュ

設定に依存しない部分（足の窓関数・銘柄一覧の結合・決算の突き合わせ）を
`data/jquants/_panel_cache/panel-<鍵>.parquet` に落とし、2 回目以降はそこから読む。
1 本 116MB。

- **キャッシュは設定に依存しない。** 母集団の判定（`eligible` / `short_eligible`）も
  時価総額の 3 分位も、読み出し側が Go で当てる（`universe.Eligible` / `ShortEligible` /
  `CapTerciles`——前夜の `plan` と同じ関数）。おかげで `config/daytrade` と
  `config/daytrade_margin` が同じキャッシュを使う
- **鍵**は「版・窓の日数・売買代金の下限（設定ではなく固定値 `PanelTurnoverFloor` = 5,000 万円）・
  読む Parquet の一覧と大きさ・更新時刻」。日次の `jquants sync` で足が増えれば鍵が変わり、
  作り直す（古いものは消す）
- 読み出しは **1 年ずつ**に分ける。日ごとに区切って 3 分位を出すので SQL 側に並べ替えが要るが、
  10 年ぶん（490 万行）を 1 度に並べるとピークが 2.5GB 増える
- **期間は鍵に入れない。** 1 本で全期間・IS・OOS のどれにも使う。期間の終わりは
  `next_open_d`（次の足の日付）で切る——「最終営業日で切る」では、上場廃止・売買停止で
  期間末より前に足が途切れた銘柄の `next_open` を取りこぼす（実測で 1 件・205 円ずれた）
- **SQL を変えたら `panelCacheVersion` を上げる**（`pkg/daytrade/backtest/panelcache.go`）。
  上げれば鍵が変わって作り直される
- 作れないときは警告を出して従来の経路で続ける（遅いだけで結果は同じ）
- 1 回だけの実行は速くならない（作成ぶんを払う）。**格子を回す研究のための道具**

根拠と実測は研究ノート 2026-09-daytrade-backtest-perf。

前夜の `plan` と同じ判定（`universe.Eligible` / `ShortEligible`）と寄付と同じ順位付け
（`selection.Rank` / `RankShort`）をアーカイブのパネルに当てる。検証と実運用で条件が
ずれないための構造。

検証と実運用を揃えるための約束事（`pkg/daytrade/backtest`）:

- **約定モデル**（`FillModel`）: 順位付けと株数は日足の寄付で決め、建値・手仕舞い値だけを差し替えられる。
  既定は寄付で建てて引けで手仕舞う（`OpenCloseFill`、滑りなし）。実運用は寄成（始値）か 9:00 以降の成行で建て、
  15:20 の成行で手仕舞うので寄付・引けとはずれる。`--fill-entry` / `--fill-exit` に時刻を渡すと**分足**（`backtest.MinuteBars`）で
  「その時刻以降の最初の約定」を建値・手仕舞い値にする。分足の履歴は 2 年しか無いので、
  **分足の無い日は日足の寄付・引けにそのまま落ちる**（10 年の検証はこの指定でも止まらない。
  どこからが分足かは出力の 1 行目に出る）。板が無いのでスプレッドの半分は見ていない。
  分足での検証は vault `20-research/2026-09-jp-gap-minute`——
  引けの板寄せは両脚に逆風（15:20 のほうが良い）で、今の日足の検証は保守的
- **既に寄っている銘柄**（`signal.skip_opened`）: 実運用は気配（始値が入っているか）で、検証は
  分足の最初の約定が 09:00 かで判定する。**分足の無い日は判定しない**——設定を真にしても
  10 年の検証の挙動が期間の前半で変わらないようにするため
- **資産曲線ゲートの窓**: 実運用（`recentPnL`）と同じく、台帳の定義（約定単価の差 × 数量。現物の手数料は含まない）で、
  止めた日は 0、縮めた日はその倍率で数える。窓に建てた日が 1 日も無ければ判定しない（12 月を休んだ直後の 1 月に
  「損益 0 ≤ 0」で縮めない）
- **張り付き**: 引けが制限値幅に張り付いた取引（売建のストップ高・買建のストップ安）は `margin.carry_penalty` の
  割合で翌寄りに置き換える。両脚とも
- **選定**: 順位付け・2 段階選定・業種上限・配分・株数は**本番と同じ関数**を呼ぶ
  （`selection.Rank` / `RankShort` → `PickFrom`）。検証側に別実装は無い。パネルの 1 行を
  前夜の候補と 9:00 の気配に写す変換だけが `backtest/bridge.go` にある。ギャップは本番と同じく
  4 桁に丸めてから帯と順位に使い、ストップ安・ストップ高の除外（`skip_limit_down` /
  `skip_limit_up`）も `Rank` / `RankShort` の判定に従う。
  配分は候補が N に満たない日も総予算（1 注文の予算 × N）を分け合い、売建は 50 単元で頭打ち
- **母集団**: 売買代金の中央値と 20 日ボラは足が所定の本数揃った銘柄だけ（パネルと前夜の `plan` で同じ）。
  株式分割・併合の日は建てない（前夜に係数を知り得ない）。日次リターンと翌寄りは `AdjFactor` で揃える。
  実運用の 9:00 は立花証券の基準値段（`pPRP`）でギャップを出すので、分割日に −50% のギャップとして候補に乗ることはない。
  パネル側で落とすのは「帯にどう転んでも入らない」行だけ（`outsideGap`。10 年ぶんの候補を
  decimal に変換する手間を削る粗ふるいで、境界の銘柄は余裕を付けて必ず `selection` に渡す）
- **縮めた日の取引**（`--trades`）: 株数・損益にその日の倍率を掛けた値。日次の集計と一致する

## 履歴（振り返り・検証用）

台帳は「今日もう建てたか」に答えるための現在の状態で、dry-run の記録は確認のたびに消す。
ログは順位表の上位 N+5 件しか持たず 90 日で消える。日々の振り返りと検証に要る
「何が候補で、何を選び、何を選ばなかったか」は `state/daytrade/history/<種類>/` に
**追記専用の Parquet** で残す。1 回の `plan` / `open` が 1 ファイル
（`<判定日>T<時刻>Z-<run_id>.parquet`）で、同じ日に何度走っても上書きしない
（cron の 8:59:50〜9:13 の各回も、dry-run の確認も全部残る）。

| 種類 | 1 行 | いつ |
|---|---|---|
| `plan` | 母集団の 1 銘柄（`eligible` / `short_eligible` と除外理由の列ごと。`margin_ratio` は記録だけ。`earn_yield` / `ret1` / `ret5` / `ret20` / `pos20` / `prev_intraday` は LightGBM の特徴量） | `plan` のたび |
| `plan_meta` | `plan` 1 回の要約（件数・IV・ドリフト。`rerank_features` は特徴量を書いた版で、0 なら `lgbm` で並べられない） | `plan` のたび |
| `quotes` | `open` が受け取った気配 1 銘柄。`usable`（鮮度の検査を通った）・`opened`（もう寄っていた）・`gap` 付き | `open` が気配を取ったとき |
| `ranking` | 順位表の 1 行。`side`（BUY=ロング / SELL=ショート）、`picked`、`quantity`、`amount`。`over_budget` は 1 単元が 1 注文の予算を超えて飛ばされた銘柄（順位が上でも picked にならない）。`skipped` は危険信号で見送った日の順位表で、picked は「建てていたら」（N と予算は通常日の値）。`reason` は選ばれた／外れた理由（`picked` / `over_budget` / `sector_cap` 業種の上限 / `value_pool` 益回りで N に入らず / `too_small` 按分が 1 単元未満 / `beyond_n` N の外。2026-09-15 から）。`rule_rank` は gap_vol での順位、`rule_picked` は gap_vol の順位なら選んでいたか、`score` は LightGBM の予測値（`rank` はこの高い順。LightGBM で並べた日だけ。2026-09-18 から）。`rule_off` は既存規則なら建てない日（米国小幅高）で、`rule_picked` が 0 件なのは候補なしではない | `open` が順位を付けたとき（見送りの日も） |
| `open_run` | `open` 1 回の要約。`mode`（live / dry_run / watch）、`outcome`（picked / regime / no_quotes / no_picks / no_capital）、危険信号の値、件数、`rank_by`（ロングを実際に並べた規則）、`us_low`（米国小幅高の日）、`preopen_limit_pct`（その回の寄指の位置。0 = 寄成）、`opening_limit_dropped`（指値を作れず外した数）。後ろの 3 つは 2026-09-21 から（古いファイルには無いので `union_by_name = true`） | `open` が判断まで進んだとき |
| `open_run` の `broker_verify` | 実機検証の実行（`--broker-verify`）だったか | `open` のたび |
| `book` | 板・気配 1 銘柄 × 1 観測時刻（`slot` = JST の HHMM）。時価問合の応答をそのまま（値は文字列） | `snap` のたび（1 日 13 回。[OPENING_DATA.md](OPENING_DATA.md)） |

全ファイルに `day`（判定日）・`run_id`（ログと同じ）・`recorded_at`（UTC）が付く。
「その日の最終判断」は `recorded_at` が最大の `run_id`（`--latest`）。
「なぜ X が選ばれなかったか」は `ranking` に無ければ `quotes`（ギャップが条件外・ストップ安・気配なし）で追える。

```bash
daytrade history                                  # 種類ごとのファイル数と期間
daytrade history ranking --date 2026-09-03 --latest
daytrade history open_run --from 2026-09-01 --csv /tmp/open_run.csv
```

分析は DuckDB で直接読む（列が増えても古いファイルはそのまま読める）:

```bash
jquants query "SELECT * FROM read_parquet('state/daytrade/history/ranking/*.parquet')
               WHERE picked ORDER BY day, recorded_at"
```

`state/` はホスト固有なので、`state/daytrade/history/` も台帳と同じく別ホストへ同期する（`docs/DEPLOY.md`）。

## 板・気配の記録（`snap`）

**集めるだけで、選定には使わない。** 今の選定は時価問合の 6 列（`pDOP,pDPP,tDPP:T,pPRP,pQBP,pQAP`）から
ギャップ 1 変数を作っているだけなので、「どんな気配なら勝率が上がるか」に答えるデータが無い。
板は過去に遡れず、記録を始めた日からしか手に入らない——設計・容量・実機で確かめることは
[OPENING_DATA.md](OPENING_DATA.md)。

```bash
daytrade snap                        # 今この瞬間の板を plan の全銘柄ぶん記録する（cron）
daytrade snap --symbols 7203,9984    # 疎通確認
daytrade quotes --raw --columns "pDOP,pDPP,..." 7203   # 応答をそのまま見る（列名の確認）
daytrade history book --date 2026-09-08 --csv /tmp/book.csv
```

- 設定は `[book]`（`enabled` / `scope` / `columns`）。`scope = "all"` は plan の**全行**（除外された
  銘柄も含む ＝ 実質全上場）。母集団の条件を将来変えたくなったとき、条件の外にあった銘柄の
  板が無いと検証できない
- **応答に返った列は指定の有無にかかわらず全部記録する**。値は解釈せず文字列のまま
  （J-Quants アーカイブと同じ「生のまま残す」流儀）。立花が返す列が増えても設定に足すだけで、
  古いファイルは `union_by_name` でそのまま読める
- cron は `open` / `close` と**同じロック**を使う。時価問合のレート制限（8 回/秒。2026-09-21 に 4 から上げた）はプロセス内なので、
  同時に走ると発注側が弾かれうる。取れなければ `snap` は何もせず終わる（発注が優先）

## 実機検証の印（`--broker-verify`）

発注経路を実機で確かめるとき（[BROKER_VERIFY.md](BROKER_VERIFY.md)）は、`open` / `close` /
`verify` に `--broker-verify` を付ける。**`env` では切り分けられない**——本番口座で
確かめることがあり、印が無いと後からログを読む `night-repair` / `daily-report` が
「時間外の発注」「持ち越し」を本当の異常として拾う。

- ログの**全行**に `verify: true`、ダイジェストにも `verify: true`
- 台帳の注文に `verify` の印（`daytrade status` では「（検証）」付きで並ぶ）
- 検証で建てた玉は**本物**なので `close` / `verify` は普段どおり手仕舞う
- 外れるのは**成績の集計だけ**——`evaluate` / `review` / `trades` と、
  資産曲線のゲート（直近 20 日の実現損益）。1 単元の検証取引で翌日の資金が
  半分に縮まないようにするため。検証の注文しか無い期間は「建てていない」と同じで、ゲートを効かせない
  （`ledger.RecentPnL`）

## 候補の結果と選定の妥当性（`evaluate` / `review` / `trades`）

建てなかった候補（次点、順位表の残り）がその日どう動いたかを追えないと、選定が妥当か
分からない。`daytrade evaluate` は大引後に朝の順位表の**全行**へ当日の日足を当て、
「建てていたらいくらだったか」を `history/evaluation` に残す（1 回 1 ファイル、上書きしない）。

- 順位表は 9:00 の記録（`ranking_source = quotes`）を使う。**無い日は前夜の plan と当日の
  始値から同じ規則で作り直す**（`archive_open`。バックテストと同じ近似）。発注経路を止めて
  `open` を回していない間でも評価は毎日積める
- 1 行 = 候補 1 銘柄。`rank_group`（picked / next / rest）、始値・終値、`gross_bp`（寄付 → 大引を
  建て方向で見た bp）、`cost_bp`（滑り・貸株料等の見込み）、`net_bp`、`hypo_quantity` / `hypo_pnl`
  （選んだ銘柄は記録の株数、それ以外は予算で買える株数）、`even_quantity` / `even_pnl`（全行を
  「1 注文 = 予算の等金額」で揃えた株数と損益。**選び方どうしを円で比べるのはこちら**——
  `hypo_pnl` は選んだ銘柄だけ按分の株数なので物差しが違う）、`limit_up_close` / `limit_down_close`
  （売建の持ち越しリスク）、`traded` / `actual_pnl`（台帳の本発注の約定）
- `rule_rank` / `rule_picked` / `score` は LightGBM で並べた日の既存規則（gap_vol）での順位・
  既存規則なら選んでいたか・予測値（2026-09-18 から。それより前は null）。表示では既存規則の選定に
  `r` が付き、「LightGBM と既存規則の比べ」（件数・平均 net bp・想定損益・重なり）が出る。
  同じ中身をログ `daytrade.rule_compare` に残す。`rule_off` は**既存規則なら建てない日**
  （米国小幅高。gap_vol は `us_skip_legs = "all"` で両脚とも休む）で、その日の `rule_picked` は
  0 件が正しい姿。`later_run` は 1 回目の後の回で建てた行で、実績には入るが選び方の比べからは外す。
  横断で比べるなら:

  ```bash
  jquants query "WITH e AS (SELECT * FROM read_parquet('state/daytrade/history/evaluation/*.parquet', union_by_name = true)
                 QUALIFY run_id = arg_max(run_id, recorded_at) OVER (PARTITION BY day))  -- 1 日は最後の評価だけ
                 SELECT count(DISTINCT day) AS days,
                        avg(net_bp) FILTER (WHERE picked) AS lgbm_bp, sum(even_pnl) FILTER (WHERE picked) AS lgbm_pnl,
                        avg(net_bp) FILTER (WHERE rule_picked) AS rule_bp, sum(even_pnl) FILTER (WHERE rule_picked) AS rule_pnl
                 FROM e WHERE side = 'BUY' AND score IS NOT NULL AND NOT skipped
                        AND NOT coalesce(later_run, false)"  -- 後の回で建てた行は 1 回目の選定ではない
  ```
- `actual_entry` / `actual_exit` は約定単価、`ref_entry` / `ref_exit` は**注文を送る直前**に
  照会した時価（台帳の `ref_price`）。約定単価と日足の差には「判断から発注までの遅れ」が
  混じるので、執行そのものの滑りはこの `ref_*` との差で見る。`open` は選定の気配を取り始めてから
  3 秒以内に発注へ進んだ回に限り、取り直さずにその気配を `ref_entry` に使う（往復 1 つ、約 0.26 秒を
  省く。ログ `daytrade.ref_price` の `reused`）。判定が長引いた回と `close` / `guard` は従来どおり取り直す
- `midday` / `midday_gross_bp` / `midday_net_bp` は**前場引け**（11:30 までの最後の約定値）で
  手仕舞っていたら。ロングの利益は前場で出尽くし、10:30〜11:25 に前倒しすると利益 −6〜10% で
  MaxDD が半分になる（2 年の検証。vault `20-research/2026-09-jp-gap-minute` の発見 2）。**既定の出口は 15:20 のまま**で、効きが続くかを毎日ここで測る。分足の
  アドオンが無い日は null
- `quotes` の日は `gap`（9:00 の気配）と `gap_open`（実際の始値）の差で、気配の当たり具合も見える

```bash
daytrade evaluate --config-dir config/daytrade_margin                 # 今日（cron: 17:05・17:20・20:20）
daytrade evaluate --date 2026-09-02 --config-dir config/daytrade_margin
daytrade review                                                       # 直近 20 日
daytrade review --from 2026-09-01 --csv /tmp/review.csv
```

`daytrade trades` は**建てた 1 銘柄ずつの明細**。レポート（日次・週次・月次）が
「何を、いくらで建てて、いくらで手仕舞い、なぜ勝った（負けた）か」を書けるように、
1 行 1 取引で並べる。

```bash
daytrade trades --config-dir config/daytrade_margin              # 直近 20 営業日
daytrade trades --from 2026-09-01 --to 2026-09-30 --json         # 期間を指定（AI・パイプ用）
daytrade trades --side SELL --csv /tmp/short.csv                 # 脚で絞って書き出す
```

- 1 行 = 銘柄名・株数・**建値**・**手仕舞い値**・ギャップ・net bp・円損益。建値と手仕舞い値は
  台帳の**約定単価**があればそれ（`priced = 実`）、無ければ日足の始値・終値（`想定`）。
  日足の値（`bar_open` / `bar_close`）も残すので、その差が**検証との差**になる
- `exec_bp` は**執行そのものの滑り**——注文を送る直前の時価（`ref_entry` / `ref_exit`）と
  約定単価の差を建てと手仕舞いで足したもの（不利なら負）。**検証との差が大きく `exec_bp` が
  小さければ、原因は執行ではなく発注の遅れ**（2026-09-15 の本番初日がこれで、
  9:01 の見送りのあと 9:13 に建てたぶん寄付より 2〜3% 高く買っていた）
- `cause` は勝敗の主因の 2×2。その日その脚の**候補全体の平均**と同じ向きなら「地合い」、
  逆なら「選定」。**選定勝ちが選定負けを上回っているか**が順位付けの価値で、
  地合いの勝ちは相場に乗っただけ（規則の証拠にならない）
- 合計には勝率のほかに、**ペイオフ**（平均利益 ÷ 平均損失）、**1 取引の期待値**、
  **利益の集中**（上位 1 件・3 件で稼ぎの何割か）、**検証との差**と**執行の滑り**、張り付きの件数が出る。
  勝率だけでは判断できない——勝率 33% でもペイオフ 2.0 なら期待値は正で、
  逆に 1 件で稼ぎの 8 割なら、その 1 件が再現しない前提で読む

`review` は日 × 脚ごとに「選んだ N の平均 net bp」「次点の平均」「候補全体の平均」と想定損益・
実現損益を並べ、期間の合計に「picked が勝った日」「picked が all を上回った日」の割合を出す。
選定が効いていれば picked ≥ next ≥ all の日が多い。逆が続けば、順位付けの規則（ギャップの
小さい順／大きい順）がその相場で効いていない合図。

危険信号で見送った日は `skipped`（`evaluation` と `review` の列。表示は「見送」）。`open` が
見送りの日も通常日の N と予算で順位表を書くので、「建てていたら」が気配の順位表で評価される
（2026-09-14 までの見送りの日は始値の作り直しに、`open_run` の結末から印を付ける）。
**期間の合計は脚ごとに通常日と見送りの日の 2 行に分かれる**——見送りの日の picked が
負けていれば見送りは正しかった、勝ち続けていれば危険信号の規則を見直す材料。
`over_budget` は 1 単元が予算を超えて飛ばされた銘柄で、値がさ株の取り逃がしを追える。
全行は DuckDB で直接読める:

```bash
jquants query "SELECT rank_group, avg(net_bp) FROM read_parquet('state/daytrade/history/evaluation/*.parquet')
               WHERE side = 'SELL' GROUP BY rank_group"
```
